# M1-1 代码整理：五个文件各在干什么

> 配套代码在 `M1/M1-1/src/`。这份文档只讲“每块负责什么”，不抠语法。

## 先记住骨架

所有 ROS2 节点文件都是**五块**，顺序固定：

| 块 | 内容 | 你要做的事 |
|---|---|---|
| 1 | `import` 开头几行 | 照抄 |
| 2 | `class Xxx(Node):` | 照抄，只改类名 |
| 3 | `def __init__(self):` | 照抄结构，改里面建的东西 |
| 4 | 某个函数（`tick` / `on_data` / `on_distance`） | **这是业务逻辑，要懂** |
| 5 | `def main(...)` | 照抄 |

**三个节点文件（A/B/C）都是这个骨架**，区别只在块3 建了什么、块4 干什么。

| 文件 | 块3 建了什么 | 块4 叫什么 | 块4 什么时候被调用 |
|---|---|---|---|
| `node_a_sensor.py` | 发布者 + 定时器 | `tick` | 每 0.1 秒（定时器叫它） |
| `node_b_filter.py` | 参数 + 订阅者 + 发布者 | `on_data` | 收到 `/sensor_data` 消息时 |
| `node_c_alarm.py` | 参数 + 订阅者 + 服务客户端 + 定时器 | `on_distance` / `check_timeout` | 收到消息时 / 每 0.1 秒 |
| `alarm_server.py` | 服务端 | `on_request` | 有人来调服务时 |

---

## 一、`alarm_server.py`（最简单，先看这个）

**块3** 只建了一样东西：

```python
self.create_service(TriggerAlarm, 'trigger_alarm', self.on_request)
```

意思：在 `trigger_alarm` 这个名字上开一个服务，类型是 `TriggerAlarm`，**有人来请求就执行 `on_request`**。

**块4**：

```python
def on_request(self, request, response):
    ...打印日志...
    response.success = True
    response.response = '报警已处理'
    return response
```

`request` 是对方发来的内容，`response` 是要回给对方的。**填好 `response` 再 `return`，对方才收得到。**

> 这跟“接电话”一样：铃响 → 听对方说什么（request）→ 回答（response）→ 挂断（return）。

## 二、`node_a_sensor.py`（造数据的人）

**块3** 建了两样：

```python
self.pub = self.create_publisher(SensorData, 'sensor_data', 10)   # 发布者
self.create_timer(0.1, self.tick)                                  # 定时器
```

- 第一句：在 `sensor_data` 上开一个发布者，能发 `SensorData` 类型的消息。
- 第二句：**每 0.1 秒叫一次 `tick`**。注意这只是“登记”，真正开始叫是 `spin` 之后。

**块4（tick）** 干三件事：

```python
msg = SensorData()                            # 1. 造一条空消息
msg.distance = 0.65 + 0.5 * math.sin(...)     # 2. 填字段（用正弦造波动）
msg.status = 1 if self.n % 20 == 10 else 0    #    每 20 帧塞一个"无效"
self.pub.publish(msg)                         # 3. 发出去
```

**为什么用正弦**：让距离自己在 0.15~1.15 米之间来回摆，这样一定会低于 0.3，能触发报警。

## 三、`node_b_filter.py`（滤波的人）

**块3** 建了三样：

```python
self.declare_parameter('alpha', 0.3)                                        # 参数
self.sub = self.create_subscription(SensorData, 'sensor_data', self.on_data, 10)  # 订阅
self.pub = self.create_publisher(Float32, 'processed_distance', 10)         # 发布
```

- `declare_parameter` = **声明**一个参数。不声明，`ros2 param set` 改不了（我试过，报 `has not been declared`）。
- 订阅和发布是对称的：一个听、一个说。

**块4（on_data）** 三步：

**第一步：丢掉无效数据**

```python
if msg.status != 0:
    self.get_logger().warn(...)
    return          # 直接结束，不往下走
```

**必须放在滤波之前**——否则无效值会污染 `y`，后面几帧都跟着歪。

**第二步：滤波**

```python
alpha = self.get_parameter('alpha').value      # 每次现读，所以外部改了立刻生效
if self.y is None:
    self.y = msg.distance                      # 第一帧没有"上次"，直接用
else:
    self.y = alpha * msg.distance + (1 - alpha) * self.y
```

`alpha` 越小，新数据权重越低，输出越平滑、跟随越慢。

**第三步：发出去**

```python
self.pub.publish(Float32(data=float(self.y)))
```

## 四、`node_c_alarm.py`（判断并报警的人）

**块3** 建了五样：

```python
self.declare_parameter('alarm_threshold', 0.3)    # 阈值
self.declare_parameter('service_timeout', 1.0)    # 超时
self.declare_parameter('cooldown', 2.0)           # 冷却（后加的）
self.sub = self.create_subscription(...)          # 订阅滤波结果
self.client = self.create_client(TriggerAlarm, 'trigger_alarm')   # 服务客户端
self.create_timer(0.1, self.check_timeout)        # 专门查超时的定时器
```

**块4 有两个函数**，分工明确：

### `on_distance`：收到距离就判断

```python
if msg.data >= threshold:  return      # 距离够远，不管
if self.future is not None: return     # 上次的请求还没回来，别叠加
# 冷却判断（后加的五行）
self.future = self.client.call_async(req)     # 发出去，不等待
self.send_time = self.get_clock().now()
self.last_alarm_time = self.get_clock().now()  # 记下这次的时间
```

### `check_timeout`：每 0.1 秒看一眼

```python
if self.future is None: return          # 没在等，什么都不做
if self.future.done():                  # 回话了 → 读结果
    resp = self.future.result()
    self.future = None                  # 清空
    return
if 等了多久 > service_timeout:           # 没回话且超时 → 警告
    self.get_logger().warn('[WARN] 报警服务超时')
    self.future = None
```

**为什么拆成两个函数**：`call_async` 发出去立刻返回，不等结果；所以需要另一个地方的定时器反复检查“结果回来没”。**这就是题目说的“不能阻塞回调”。**

---

## 五、后加的冷却，三处位置

| 位置 | 加的代码 | 作用 |
|---|---|---|
| 块3 参数区 | `declare_parameter('cooldown', 2.0)` + `self.last_alarm_time = None` | 准备一个“上次报警时间”的变量 |
| `on_distance` 中间 | 算 `gap`，`gap < cooldown` 就 `return` | 不够 2 秒就不报 |
| `on_distance` 末尾 | `self.last_alarm_time = self.get_clock().now()` | 报完记下时间 |

**一句话概括**：报警前先看表，距上次不够 2 秒就先别报。

---

## 六、三处“改错会怎样”（答辩常问）

| 改错什么 | 现象 |
|---|---|
| 删掉 `declare_parameter` | `ros2 param set` 报 `Parameter 'alpha' has not been declared` |
| 把 `status` 判断挪到滤波之后 | 无效数据污染 `y`，后面几帧的滤波值都不对 |
| 把 `call_async` 换成 `call()` | 节点卡死，超时检测的定时器也跑不了 |

---

## 七、一句话总结

**A 造数据、B 洗数据、C 看数据要不要报警；服务端负责应答。四者之间只通过话题和服务名联系，谁也不知道对方的代码长什么样。**
