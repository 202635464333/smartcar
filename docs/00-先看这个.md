# 先看这个（一页纸讲清你手上的所有工具）

> **只看这一份就够了。** docs 里另外两份（工具链说明、命令逐条讲解）是参考手册，卡住时再查，不用通读。

---

## 第 1 节：一句话

**你电脑里有两个系统，共用一块硬盘。**

不是两个分区、不是两个用户，是**两个操作系统**。一个 Windows，一个 Ubuntu。

`C:\Users\lenovo` 和 `/home\lenovo` 是两个完全不同的地方。名字像，但互不相干。

---

## 第 2 节：五个东西，一句一个

| 东西 | 一句话 |
|---|---|
| **Windows** | 开机看到的就是它，管硬件。但它**没有 ROS2** |
| **WSL + Ubuntu** | Ubuntu 是另一个系统（Linux），借 WSL 住在 Windows 里。ROS2 只能装在它里面 |
| **ROS2 + Python** | 装在里面的一整套工具。**你的代码就是"用 Python 指挥 ROS2"** |
| **VS Code** | 只是编辑器，**它不运行程序**。它能改 Ubuntu 里的文件，是因为装了个插件在 Ubuntu 里跑了个小服务 |
| **Git / GitHub** | Git 在你电脑上拍快照；GitHub 把快照放云上 |

---

## 第 3 节：文件到底在哪

打开两个窗口对比一下就懂了：

- VS Code 终端敲 `pwd` → 显示 `/home/lenovo/study`
- Windows 资源管理器地址栏输 `\\wsl$\Ubuntu\home\lenovo\study` → 同一个文件夹

**同一个文件夹，两个系统两套地址。**

你的代码必须在 `/home` 这边，不能放 `C:\` 那边。原因两条：

1. 跨系统读写慢
2. 权限会乱，可能莫名报 `Permission denied`

---

## 第 4 节：你每天干什么

就五步：

1. 打开 VS Code（自动连上 Ubuntu）
2. 打开 `~/study` 文件夹
3. 终端敲 `source /opt/ros/humble/setup.bash`
4. 写代码、跑 `ros2 run`
5. 收工前：`git add -A` → `git commit -m "说明"` → `git push`

**只有第 3 步是必须记住的。**

为什么每次都要敲？因为"环境变量"只活在这个终端窗口里，你一关窗口就没了，新开的是空白。

---

## 第 5 节：最容易搞错的三条

**① "VS Code 是运行环境"——错**
程序跑在 Ubuntu 里，VS Code 只是笔。你在它里面点"运行"，其实是它在 Ubuntu 里帮你敲了命令。

**② "GitHub 就是 Git"——错**
Git 是装在你电脑上的程序，断网也能用；GitHub 是网站。`commit` 存本地，`push` 才上传。

**③ "`source` 敲一次就永久生效"——错**
只对当前这个终端有效。新开终端必须重敲。

判断有没有搞混的办法：**看 VS Code 左下角**。写着 `WSL: Ubuntu-22.04` 才是连对了。

---

## 第 6 节：最常用的五条命令

```bash
pwd                                   # 我在哪
ls                                    # 这有什么
cd ~/study                            # 过去
source /opt/ros/humble/setup.bash     # 激活环境（每个新终端都要）
git status                            # 现在有什么改动
```

- 迷路时用前两条
- 每次开终端用第四条
- 提交前用第五条

---

## 第 7 节：三句话总结

1. **Windows 和 Ubuntu 是两个系统，代码放 `/home` 那边。**
2. **VS Code 是笔，ROS2 是工具，`source` 是每次开新终端的"开锁"动作。**
3. **`commit` 是存本地，`push` 才是上传。**

## 卡住时的查表

| 报错 / 现象 | 病因 | 怎么办 |
|---|---|---|
| `command not found` | 找不到程序 | 没装，或忘了 `source` |
| `No such file or directory` | 路径不存在 | 先敲 `pwd` 看自己在哪 |
| `Permission denied` | 权限不足 | 别在 `/mnt/c` 下操作 |
| 改完代码没反应 | 没重新运行 | 程序要手动 `ros2 run`，不会自动跑 |
