# 工具链说明：Ubuntu / WSL / ROS2 / VS Code / Git / GitHub 到底是什么

> 这份文档只回答一个问题：**我这一堆软件，各自在干嘛？**
> 每条都给了你自己验证的命令，看完能亲手证明，不是听我说。

---

## 一、先记住一句话

**你电脑里现在有两个操作系统，共用一块硬盘。**

- 一个是 Windows（你开机看到的桌面）
- 一个是 Ubuntu（Linux，藏在 Windows 里面，装在 WSL 里）

它们各有各的文件夹：

| 系统 | 家目录 | 你平时怎么进去 |
|---|---|---|
| Windows | `C:\Users\lenovo` | 开机就是 |
| Ubuntu | `/home/lenovo`（=`~`） | 打开 Ubuntu 终端 |

**这是最核心的一条**：`C:\Users\lenovo` 和 `/home/lenovo` 是两个不同的地方，长得像，但完全不相干。你之前把代码放错地方，就是因为这个。

---

## 二、逐层讲

### 第 0 层：Windows —— 一切的地基

你开机看到的就是它。浏览器、微信、QQ、SolidWorks 都在这里跑。

它管的是硬件：CPU、内存、硬盘、显示器。

**它没有 ROS2。** 这就是为什么你在 Windows 的 cmd 里敲 `ros2` 会报"不是内部或外部命令"。

### 第 1 层：WSL + Ubuntu —— Windows 里的另一个房间

**WSL** = Windows Subsystem for Linux，微软做的一个功能：让 Linux 能在 Windows 里直接运行，不用装虚拟机、不用重装系统、不用双系统。

**Ubuntu** 是 Linux 的一个发行版（Linux 有很多"品牌"，Ubuntu 是最常用的那个）。ROS2 的官方支持列表里，Ubuntu 22.04 是 Humble 版本的标准搭配。

**怎么证明它在？** 打开任意终端，敲：

```bash
lsb_release -a
```

看到 `Ubuntu 22.04.5 LTS` 就对了。

**三种进去的方式**（效果一样，选一个顺手的）：

1. 开始菜单搜 "Ubuntu" → 打开一个紫色/黑色的窗口
2. 按 `Win + R`，输入 `wsl`，回车
3. VS Code 里的终端（推荐，见第 3 层）

**关键概念：两个系统的文件互相看得见。**

- Ubuntu 里看 Windows 的 C 盘 → 路径是 `/mnt/c/Users/lenovo`
- Windows 里看 Ubuntu 的家目录 → 资源管理器地址栏输入 `\\wsl$\Ubuntu\home\lenovo`

```bash
ls /mnt/c/Users/lenovo        # 在 Ubuntu 里看 Windows 的文件
```

**但是：你的代码必须放在 Ubuntu 侧（`/home/lenovo/...`），不要放在 `/mnt/c/...`。**

原因有三：
- 跨系统读写慢（差 3~10 倍）
- Linux 的文件权限在 `/mnt/c` 上会乱（可能出现 Permission denied）
- 有些工具（如 colcon）会因权限问题报奇怪的错

### 第 2 层：ROS2 + Python —— 装在第 1 层里的工具箱

**ROS2 不是操作系统**，尽管名字里有 OS。它是一大堆库 + 命令 + 工具程序，作用是：

- 让不同程序之间能发消息（话题通信）
- 管理坐标系（TF2）
- 提供建图、导航、仿真的现成组件（Nav2、Gazebo）

**Python** 是你指挥它的语言。你的代码本质上是"用 Python 调用 ROS2 提供的函数"。

**怎么证明它在？**

```bash
source /opt/ros/humble/setup.bash     # 先"激活"
ros2 --version                         # 看版本
ls /opt/ros                            # 看到 humble 这个文件夹
```

**注意 `source` 这个动作**：ROS2 装在 `/opt/ros/humble`，系统默认不知道这个路径。`source` 的作用是"把这个路径告诉当前这个终端"。

它是**一次性的**——关掉终端就失效，新开终端要重新敲。这是你昨晚踩的坑。

### 第 3 层：VS Code —— 只负责写字，不负责运行

**这是你最可能误解的一个。**

VS Code 是**编辑器**，它的本职工作是：让你敲字时有颜色高亮、有自动补全、有报错提示。它**不运行你的程序**。

那为什么在 VS Code 里点运行，程序能跑起来？

因为 VS Code 装了一个叫 **Remote - WSL** 的扩展。它的原理是：**在 Ubuntu 里偷偷跑一个小服务（`~/.vscode-server`），Windows 这边的界面通过它去读写 Ubuntu 里的文件。**

所以：

- VS Code 窗口的**界面**运行在 Windows 上
- VS Code 打开的**文件**存在 Ubuntu 里
- VS Code 里的**终端**是 Ubuntu 的终端

**判断你有没有连上 Ubuntu**：看左下角那条绿色状态栏。

- 写着 `WSL: Ubuntu-22.04` → 连上了，改的是 Ubuntu 里的文件
- 空白 / 写着别的 → 你在改 Windows 里的文件，ROS2 跑不起来

**怎么证明编辑器管不了环境？** 在 VS Code 里改一行代码保存，程序不会自动重新运行——必须你自己在终端敲 `ros2 run`。编辑器只管字。

### 第 4 层：Git + GitHub —— 存档和云备份

**Git** 是装在你电脑上的版本管理工具。它做的事：给你的代码"拍照存档"。

**GitHub** 是一个网站。你把本地存档传上去，别人就能看，而且时间戳是服务器记的，改不了。

**两个不是一回事**：

| | Git | GitHub |
|---|---|---|
| 是什么 | 装在你电脑里的程序 | 一个网站 |
| 断网能用吗 | 能 | 不能 |
| 你的文件存在哪 | `~/study/.git` 这个隐藏文件夹 | 云端 |

**Git 的三个区域**（这是最容易懵的地方）：

```
你改的文件  →  暂存区  →  本地仓库  →  GitHub
（工作区）      (stage)    (commit)     (push)
```

对应三条命令：

| 命令 | 干什么 | 打比方 |
|---|---|---|
| `git add -A` | 把改动放进暂存区 | 把要拍的东西摆到镜头前 |
| `git commit -m "说明"` | 拍一张快照，存进本地 | 按快门，照片存在相机里 |
| `git push` | 把本地的快照传到 GitHub | 把照片上传到网盘 |

**关键**：`commit` 之后**断网也不会丢**；只有 `push` 才是传到云上。

**怎么证明有存档？**

```bash
cd ~/study
git log --oneline
```

看到 `422fede chore: 初始化仓库...` 就是你的第一条存档。

## 三、一张图看清"文件到底存哪"

```
你的电脑（一块硬盘）
│
├── C:\Users\lenovo\           ← Windows 的地盘
│   ├── Desktop\
│   ├── Documents\
│   └── ...（Windows 软件都在这）
│
└── \\wsl$\Ubuntu\home\lenovo\  ← Ubuntu 的地盘（在硬盘上的另一块区域）
    └── study\                  ← 你的代码在这！
        ├── talker.py
        ├── docs\
        └── .git\               ← Git 的存档就藏在这个隐藏文件夹里
```

两个系统的互相访问路径：

| 在哪边看 | 想看的目录 | 路径 |
|---|---|---|
| Ubuntu 看 Windows | `C:\Users\lenovo` | `/mnt/c/Users/lenovo` |
| Windows 看 Ubuntu | `/home/lenovo` | `\\wsl$\Ubuntu\home\lenovo` |

## 四、你每天的实际流程

```
1. 打开 VS Code（它自动连上 Ubuntu）
2. 打开 ~/study 这个文件夹
3. 按 Ctrl+` 打开终端，敲 source /opt/ros/humble/setup.bash
4. 改代码 / 写新节点
5. 在同一终端里 ros2 run 测试
6. 收工前：
     git add -A
     git commit -m "feat: 今天做了什么"
     git push
```

只有第 3 步和第 6 步是"必须记住"的，其余是自然动作。

## 五、常见误解（逐条澄清）

| 误解 | 事实 |
|---|---|
| "VS Code 是个运行环境" | 不是。它只是编辑器，程序跑在 Ubuntu 里 |
| "Ubuntu 是 Windows 的软件" | 它是一整套独立的操作系统，只是借助 WSL 住在 Windows 里 |
| "ROS2 是操作系统" | 不是。名字骗人，它是库 + 工具的集合 |
| "GitHub 就是 Git" | 不是。Git 是本地程序，GitHub 是网站 |
| "commit 之后代码就上传了" | 没有。要 `push` 才上传 |
| "C 盘和 /home 是一个地方" | 完全是两个位置，路径写法都不同 |
| "装了 Ubuntu 就不能用 Windows 软件了" | 能，两边共存，随时切换 |
| "`source` 敲一次就永久生效" | 只对当前终端有效，新终端要重来 |

## 六、速查命令表

```bash
# 我是谁、在哪
whoami                 # 用户名
pwd                    # 当前目录（/home/... 是 Ubuntu，/mnt/c/... 是 Windows）
lsb_release -a         # Ubuntu 版本

# ROS2
source /opt/ros/humble/setup.bash   # 激活（每个新终端都要）
ros2 --version                      # 版本
ros2 node list                      # 有哪些节点在跑
ros2 topic list                     # 有哪些话题

# Git
git status             # 现在有哪些改动
git log --oneline      # 存档历史
git add -A             # 全部放进暂存区
git commit -m "说明"   # 拍快照
git push               # 传到 GitHub
```

---

## 七、三句话总结

1. **Windows 和 Ubuntu 是两个系统，代码放 Ubuntu 那边（`/home/lenovo`）。**
2. **VS Code 只是笔，ROS2 才是工具，`source` 是每次开新终端都要做的"开锁"动作。**
3. **Git 拍本地快照，GitHub 放云上，`commit` 不等于 `push`。**
