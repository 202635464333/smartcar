# M1-1 怎么学：打开哪个链接，看完能做出什么

> 这份文档不讲知识点，只给**动作**。
> 每一行都是一个单元：打开一个页面 → 看一节 → 做一件能验证的事 → 打勾。

## 先搞清楚一件事

M1-1 要写三个节点，用到四种通信方式。**四种方式在 ROS2 官方教程里各有一节现成的例子**，你不需要自己想，照着抄改就行。

所以"M1-1 怎么学"= 把这四节的例子跑通，然后把它们拼起来。

---

## 六个单元（按顺序做，别跳）

### 单元 1｜自定义消息（1.5h）

**打开**：https://docs.ros.org/en/humble/Tutorials/Beginner-Client-Libraries/Custom-ROS2-Interfaces.html

**看**：整页。重点是 `Creating a msg` 和 `CMakeLists.txt 里那几行`。

**做完能验证**：
```bash
ros2 interface show sensor_interfaces/msg/SensorData
```
能打印出 `distance / unit / stamp / status` 四个字段。

**卡住的话**：中文看 https://fishros.com/d2lros2/ 找"接口"那一章。

---

### 单元 2｜参数（1.5h）

**打开**：https://docs.ros.org/en/humble/Tutorials/Beginner-Client-Libraries/Using-Parameters-In-A-Class-Python.html

**看**：整页。就两个函数：`declare_parameter` 和 `get_parameter`。

**做完能验证**：
```bash
ros2 param set /节点名 alpha 0.9
ros2 param get /节点名 alpha
```
节点能读到改后的值。

**这是 M1-1 和 M1-2 都要用的东西，必须真跑一遍。**

---

### 单元 3｜服务（2h）

**打开**：https://docs.ros.org/en/humble/Tutorials/Beginner-Client-Libraries/Writing-A-Simple-Py-Service-And-Client.html

**看**：整页。服务端和客户端两个文件都要跑。

**做完能验证**：
```bash
ros2 service call /trigger_alarm sensor_interfaces/srv/TriggerAlarm
```
服务端打印 `[ALARM] 距离过近！`。

---

### 单元 4｜异步调用 + 超时（2h）← 这题唯一的新东西

**打开**：同一页，往下翻到 `call_async` 那部分。

**要理解的一句话**：**不能用 `call()` 阻塞等待**，因为那会把回调线程卡死。要用 `call_async()` 拿到一个 future，然后在别处检查它完成了没有。

**做完能验证**：
1. 正常跑：服务通了，日志正常
2. 把服务端 `Ctrl+C` 杀掉，再跑一次
3. **节点打印 `[WARN] 报警服务超时`，没有卡死、没有崩溃**

**这一条做不出来，M1-1 的第 3 个节点就不算完成。**

---

### 单元 5｜话题收发（已会，0.5h）

昨天已经做过（talker/listener）。M1-1 里只是换个消息类型、换个话题名。

---

### 单元 6｜低通滤波（0.2h，就一行）

不用学。公式就是：

```python
y = alpha * x + (1 - alpha) * y_prev
```

`x` 是这次收到的距离，`y_prev` 是上次算出来的结果。**没有任何数学要理解**，会写乘加就行。

## 时间账

| 单元 | 时间 |
|---|---|
| 1 自定义消息 | 1.5h |
| 2 参数 | 1.5h |
| 3 服务 | 2h |
| 4 异步 + 超时 | 2h |
| 5 话题（已会） | 0.5h |
| 6 滤波 | 0.2h |
| **合计** | **≈8h** |

比我早上说的 4-5h 要多。**8 小时是诚实的数字**，之前那个估计是按"只改现有代码"算的。

按每天 2 小时算，M1-1 要 4 天。这会把后面的排期往后推——但没办法，题目的实际要求就是这么多。

---

## 明确不用学的东西

| 不用碰 | 为什么 |
|---|---|
| C++ | 题目允许纯 Python |
| action（动作） | M1-1 用不到 |
| launch | 那是 M1-2 的事 |
| TF2 / 坐标变换 | 那是 M1-3 的事 |
| QoS 调优 | 那是 M1-4 的事 |
| 多线程 / 执行器 | 也是 M1-4 |
| 黑马剩下的集数 | 类、继承、`super` 已经够了 |

---

## 唯一要记住的顺序

**先单元 1（消息），再单元 3（服务）**——因为服务要用消息包里定义的类型。

参数和异步调用可以穿插，但不要先做异步超时：没有可用的服务，你测不出超时。

---

## 卡住时的规则

**30 分钟内没进展，就停下来**，把这三样发出去：

1. 你敲的命令
2. 完整报错（第一行 + 最后一行）
3. 你以为它会怎样

不要自己熬一晚上。这是这套 8 小时预算里最容易失控的地方。
