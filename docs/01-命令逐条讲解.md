# 命令逐条讲解：你打过的每一行到底是什么

> 目标：让每一条命令从"念咒"变成"看得懂的一句话"。
> 读完你应该能自己拆解：**这行命令是让谁、在哪儿、干什么。**

---

## 0. 终端到底是什么

终端是一个**用打字代替鼠标点击**的窗口。

- 点鼠标：打开文件夹、复制文件、运行程序
- 打命令：同样的事，只是换成文字

**为什么要用打字？** 因为远程机器（比如真正的赛车上的电脑）没有桌面可以点，只能打字。所以 Linux 世界的一切都是命令。

**关键认知：你打的每一行，回车之后都在执行一个真实的程序。** 不是"系统内置功能"，是硬盘上某个 `.exe` 一样的东西（Linux 里没有扩展名）。

---

## 1. 一行命令的解剖

```
ros2        run        demo_nodes_py        talker
 │           │              │                 │
 谁         干什么        对谁             具体哪个
（程序名）  （子命令）    （包名）          （可执行名）
```

再比如：

```
git         commit       -m        "初始化仓库"
 │            │           │             │
 程序       做什么      选项          内容
```

**三条通用规则：**

| 规则 | 说明 |
|---|---|
| 空格分隔 | 命令行里空格是"分隔符"，多一个少一个都可能报错 |
| `-` 开头的是**选项** | 开关，改变程序行为。`ls -l` 的 `-l` 就是"用长格式显示" |
| 回车才算执行 | 打一半按回车会报错或什么都不发生 |

## 2. 提示符怎么读

你屏幕上看到：

```
lenovo@LAPTOP-18V9TIKE:~/study$
```

拆开看：

| 部分 | 意思 |
|---|---|
| `lenovo` | 当前用户名 |
| `@` | 分隔符（读作 at） |
| `LAPTOP-18V9TIKE` | 计算机名 |
| `:` | 分隔符 |
| `~/study` | **你现在在哪个文件夹** |
| `$` | 表示你是普通用户（如果是 `#` 表示 root 超级管理员） |

**这个提示符不是命令的一部分**，你不需要输它。光标停在 `$` 后面，你从那里开始打字。

**最重要的信息是 `~/study`**——它告诉你"我现在站在哪个文件夹里"。所有相对路径都是从这里算起的。

---

## 3. 路径的三种写法（这是最该先搞懂的）

### ① 绝对路径：以 `/` 开头

```
/home/lenovo/study
/opt/ros/humble
```

从根目录开始，一路写到底。**不管你现在在哪，这个地址都指向同一个地方。**

### ② 相对路径：不以 `/` 开头

```
study            ← 当前目录下的 study
../docs          ← 上一级目录下的 docs
```

**跟着你当前位置变。** 你在 `~` 下，`study` 指 `/home/lenovo/study`；你在 `/opt` 下，`study` 就可能不存在。

### ③ 特殊符号

| 符号 | 含义 | 例子 |
|---|---|---|
| `~` | 你的家目录 = `/home/lenovo` | `cd ~` |
| `.` | 当前目录 | `code .` = 用编辑器打开当前目录 |
| `..` | 上一级目录 | `cd ..` |
| `/` | 根目录（所有东西的老祖宗） | `cd /` |

**记住这个对比**（你昨晚卡住就是因为它）：

```
/home/lenovo/study          ← Ubuntu 里的位置
/mnt/c/Users/lenovo/study   ← Windows 的 C 盘在 Ubuntu 眼里的位置
```

同一块硬盘，两套地址。

## 4. 你打过的命令，逐条讲

### 4.1 `pwd` —— 我在哪

**全称**：print working directory（打印工作目录）

```bash
pwd
```

**输出**：

```
/home/lenovo/study
```

**它只回答一个问题：我现在站在哪个文件夹里。**

为什么重要？因为你之前打开错了地方（在 `C:\Users\lenovo\study`），`pwd` 一敲就露馅了。**迷路时第一个该敲的命令。**

---

### 4.2 `ls` —— 这儿有什么

**全称**：list（列出）

```bash
ls          # 列出当前目录的文件
ls -l       # 长格式：权限、大小、时间
ls -a       # 包括隐藏文件（以 . 开头的）
ls /opt/ros # 列出指定目录的内容
```

**输出**：

```
docs  listener.py  talker.py
```

**为什么 `-a` 有用**：`~/study/.git` 这个文件夹默认不显示（`.` 开头 = 隐藏），加 `-a` 才看得见。

---

### 4.3 `cd` —— 走过去

**全称**：change directory（切换目录）

```bash
cd /opt/ros/humble   # 去绝对路径
cd study             # 去当前位置下的 study
cd ..                # 回上一级
cd ~                 # 回家目录
cd                   # 不写参数，也是回家
cd -                 # 回到上一次待的地方（来回跳）
```

**注意：`cd` 没有输出。** 成功就是静默的，看提示符里的路径变了就知道成功了。

**这是新手最容易怀疑自己的地方**——敲完什么都没显示，以为没成功。其实成功了。

---

### 4.4 `mkdir` —— 建文件夹

**全称**：make directory

```bash
mkdir docs                  # 建一个 docs
mkdir -p ~/study/docs       # -p = parents，父目录不存在就一起建
```

**为什么必须加 `-p`**：如果 `~/study` 不存在，`mkdir ~/study/docs` 会报 `No such file or directory`。加 `-p` 它会自动把中间缺的目录都建出来。

---

### 4.5 `cp` —— 复制

**全称**：copy

```
cp  源文件   目标位置
     ↓         ↓
cp  talker.py  ~/study/
```

```bash
cp a.py b.py            # 复制成 b.py
cp a.py ~/study/        # 复制到那个目录，名字不变
cp -r 目录1 目录2        # -r = recursive，复制整个目录（必须加）
```

**为什么复制 `/opt/ros/...` 里的文件**：`/opt` 是系统目录，改了会被系统更新覆盖，所以要抄一份出来改。

---

### 4.6 `cat` —— 把文件内容打到屏幕上

**全称**：concatenate（拼接，但实际用途是查看）

```bash
cat ~/.ssh/id_ed25519.pub    # 把公钥内容打出来
cat talker.py                # 看代码
```

**什么时候用**：文件短（几十行）用 `cat`；文件长用 `less 文件名`（可以上下翻，按 `q` 退出）。

---

### 4.7 `which` —— 这个命令的程序在哪

```bash
which ros2
```

**输出**：

```
/opt/ros/humble/bin/ros2
```

**它回答：我敲 `ros2` 的时候，系统到底执行了哪个文件。**

**为什么重要**：如果输出 `which: no ros2 in (...)`，说明系统根本找不到这个命令——要么没装，要么没 `source`。这是排查"命令不存在"的第一步。

---

### 4.8 `source` —— 激活环境（重点）

```bash
source /opt/ros/humble/setup.bash
```

`source` 不是"安装"，也不是"启动"。它的意思是：**在当前这个终端里，执行这个脚本里的每一行。**

那 `setup.bash` 里是什么？主要是**设置环境变量**，最关键的一个叫 `PATH`。

#### 什么是环境变量

想象终端里贴着一张便签纸，写着：

```
PATH = /usr/local/bin:/usr/bin:/bin
```

**你敲任何命令时，系统就照着 PATH 里列的目录，一个接一个去找这个程序。**

```
敲 ros2
  ↓
去 /usr/local/bin 找 ros2 → 没有
去 /usr/bin 找 ros2 → 没有
去 /bin 找 ros2 → 没有
  ↓
command not found
```

`source setup.bash` 之后，PATH 变成了：

```
PATH = /opt/ros/humble/bin:/usr/local/bin:/usr/bin:/bin
                 ↑
            ros2 就住在这里
```

再敲 `ros2`，第一个目录就找到了。

#### 为什么每个新终端都要重新 source

因为**环境变量只存在于当前这个终端进程里**。你关掉终端，那张便签纸就撕掉了；新开的终端是全新的，便签纸是空的。

```
终端 1：source 过 → 有 ros2
终端 2：新开的   → 没有 ros2（要重新 source）
```

**注意 `source` 和直接运行脚本的区别**：

| 写法 | 效果 |
|---|---|
| `source setup.bash` | 在**当前**终端里执行，环境变量留下来 ✅ |
| `bash setup.bash` | 开一个**子进程**执行，结束后变量全丢 ❌ |

这就是为什么必须用 `source`，不能只写 `bash`。

**成功时没有任何输出**，这也是新手会怀疑的地方。

---

### 4.9 `ros2 run` —— 跑一个节点

```
ros2      run     demo_nodes_py    talker
 │         │           │             │
程序名   子命令      包名        可执行文件
```

**拆开理解**：
- `ros2` 是总入口（一个程序，能接受很多子命令：run / node / topic / launch...）
- `run` 是子命令，意思是"运行一个包里的可执行文件"
- `demo_nodes_py` 是**包名**（一个代码包，相当于一个文件夹）
- `talker` 是包里的**可执行名**（在 `setup.py` 的 `entry_points` 里登记的那个名字）

**类似的**：

```bash
ros2 topic list     # ros2 → 子命令 topic → 操作 list
ros2 node list      # ros2 → 子命令 node  → 操作 list
```

**跑起来后按 `Ctrl+C` 停**，不是关窗口。

---

### 4.10 `code .` —— 用编辑器打开当前目录

```bash
code .          # 用 VS Code 打开"当前目录"
code ~/study    # 用 VS Code 打开指定目录
```

`. ` = 当前目录。所以 `code .` = "把我现在站的这个文件夹，用 VS Code 打开"。

**为什么能这么写**：`code` 是 VS Code 装的一个小程序，它把"路径"这个参数转给 Windows 上的 VS Code 窗口。

---

### 4.11 Git 的四条命令

```bash
git status              # 现在有什么改动（最常用，无害）
git log --oneline       # 历史存档，一行一条
git add -A              # 把全部改动放进"暂存区"
git commit -m "说明"     # 拍一张快照
git push                # 传到 GitHub
```

**解剖 `git commit -m "初始化仓库"`**：

| 片段 | 意思 |
|---|---|
| `git` | 程序名 |
| `commit` | 子命令：提交 |
| `-m` | 选项：message，后面跟说明文字 |
| `"初始化仓库"` | 说明内容。**有空格时必须加引号** |

**`-A` 是什么**：all，所有改动（包括新增和删除的文件）。

---

### 4.12 管道 `|` 和重定向 `>` `>>`

这三个符号是"命令之间的搬运工"。

#### `|` 管道：把前一个命令的输出，交给后一个命令

```bash
cat ~/.ssh/id_ed25519.pub | clip.exe
   ↑输出内容            ↑ 接收方
```

意思：把文件内容**不打印到屏幕**，而是**喂给 `clip.exe`**（复制到 Windows 剪贴板）。

#### `>` 覆盖写入

```bash
ls > 文件列表.txt
```

把 `ls` 的输出**写进文件**（文件原有内容会被清空）。

#### `>>` 追加

```bash
echo "新的一行" >> 日志.txt
```

**加在文件末尾**，不覆盖。

## 5. 一张速查表

| 命令 | 全称 | 一句话 |
|---|---|---|
| `pwd` | print working directory | 我在哪 |
| `ls` | list | 这儿有什么 |
| `cd` | change directory | 走过去 |
| `mkdir` | make directory | 建文件夹（`-p` 建多层） |
| `cp` | copy | 复制（`-r` 复制目录） |
| `mv` | move | 移动 / 改名 |
| `rm` | remove | 删除（**不可恢复，慎用**） |
| `cat` | concatenate | 看文件内容 |
| `less` | — | 分页看长文件（`q` 退出） |
| `which` | — | 这个命令的程序在哪 |
| `source` | — | 在当前终端执行脚本（改环境变量） |
| `echo` | — | 打印一行文字 |
| `|` | pipe | 把输出喂给下一个命令 |
| `>` `>>` | redirect | 输出写入文件（覆盖 / 追加） |
| `&&` | — | 前一条成功才执行后一条 |
